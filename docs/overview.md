# Project overview
Updated 2026-10-14

## What this is

`markdown-syntax` is a `no_std + alloc` Rust crate that parses one fixed
Markdown syntax into an owned AST and writes the AST back as Markdown. The
source is the only truth: a parsed document keeps its source, writing it back
keeps the bytes of every unchanged block, and canonical Markdown is the
spelling of what changed. It is the syntax layer of Settle's ProseMirror
editor, through the `markdown-syntax-wasm` binding in the same workspace. Raw
HTML is represented only as Markdown syntax nodes; safe-by-default HTML
rendering is available behind the opt-in `html` feature.

## Principles

- The default build has an empty feature set, zero runtime dependencies,
  `#![no_std]` with `alloc`, and MSRV 1.82; the crate is published, so these
  also protect downstream users.
- Default-build output stays byte-stable unless a plan changes it on purpose.
- Parsing, serialization, rendering, and validation stay linear in time and
  bounded in stack on any input.
- Bytes a user did not change are not moved by a write.
- Parser correctness fixes are checked against the serializer too, because the
  serializer can mask a stably wrong parse.
- Changed `.ast` / `.canonical.md` goldens may be regenerated by a local
  command, and each one is read for correctness in review; CI never blesses.

## Status
Shipped features are described in `docs/specs/`.

## Current focus

The editor syntax layer (`docs/plans/editor-syntax-layer/`): the kept source
and source reuse in `to_markdown`, `parse_inline`, `inline_source`, and the
WebAssembly binding with its JavaScript wrapper.

## Next

- The block model for the editor, planned from meowdown's design: every
  block spelling recorded, blank lines as content, flat lists, `#tag` in the
  syntax, and source reused per node rather than per top-level block.

## Non-goals

- HTML rendering or sanitization in the default build.
- Treating `:name` / `::name` / `:::name` directives as MDX.
- Hand-maintained ledgers of test results, conformance numbers, or task
  progress.
